# 墨境 1.0 功能与开发说明

## 1. 产品边界

墨境服务于中文长篇小说规划、写作与连续性维护。产品只借鉴成熟创作工具的抽象工作流和资料组织方式，提示词明确禁止复现已有作品的专有名词、角色、情节、体系数据和界面文案。当前版本不包含图片生成、镜头、视频提示词、制片资产、EPUB 或发布平台直传。

墨境使用独立产品身份：`cn.mojing.novel`、`.mojing-dev/mojing.db`、正式 `mojing.db` 和 `MOJING_*` 环境变量。它不读取或覆盖旧漫剧项目；旧格式 JSON 会返回可理解的“不支持”错误。

## 2. 推荐创作流程

1. 在“灵感与规格”确定题材、篇幅、视角、时态、风格、受众和内容边界。
2. 在“世界观”生成或手工维护结构化词条，并在稳定后定稿。
3. 在“小说大纲”完成总纲、主题、主冲突、结局方向、卷纲、章纲和每章剧情步骤，并定稿。
4. 在“正文创作”按章纲生成或手写。世界观或大纲缺失时 AI 正文不可执行；只有草稿时，手写和 AI 均先提示风险。
5. 在“记忆与伏笔”核对角色、关系、知识、道具、时间线和伏笔提案。未接受的提案不会进入正式上下文。
6. 在“审稿与导出”查看连续性报告、AI 修改候选和版本历史，然后导出。

用户也可以从侧栏顶部进入“AI 工作台”。工作台把六类 AI 工作组织成固定顺序，并在启动前展示 Token 占用、纳入与排除资料、权威级别、裁剪和规划警告；任务运行中可以查看进度或取消，结果仍回到对应阶段逐项确认。

定稿后的世界观或大纲一旦被修改，会自动退回草稿并建立复核任务。系统不会因此直接重写已经存在的章节。

## 3. 数据模型

- `NovelProject`：规格、状态以及所有小说聚合数据。
- `WorldBible` / `WorldEntry`：世界规则、实体、关系和时间线。
- `NovelOutline`：总纲、卷纲、章纲、每章剧情步骤与计划伏笔。
- `Chapter`：带稳定 ID 的正文段落块和内容摘要。
- `ChapterMemory`：已经确认的章节摘要、角色状态、关系、知识、道具、事实、时间与风格；角色状态和事实可以限定适用章节范围，并由后续状态明确替换。
- `MemoryProposal`：带来源章节、段落、证据、置信度、风险、生效范围和替换关系的待确认变化。
- `PlotThread`：伏笔埋设、推进、回收、放弃和逾期生命周期。
- `NovelGenerationJob`：一次 AI 运行的持久记录，保存状态、Token 估算、上下文条目、进度事件、候选编号与错误。

SQLite 使用项目、版本、AI 候选、记忆提案、模型配置、用量和 FTS5 检索表。自动保存不创建逐键版本副本；AI 应用、恢复和手工检查点会保留有意义的历史版本。

## 4. AI 与长篇上下文

公共生成类型包括：`world-foundation`、`world-section`、`outline`、`chapter`、`chapter-revision`、`memory-extraction`、`memory-rebuild`、`continuity-audit`、`foreshadow-review` 和 `branch`。

上下文按永久、状态、剧情、近期和远期召回五层构建。远期召回综合 FTS5、实体别名、章纲引用、伏笔关系和因果依赖，并在模型预算内裁剪。每次正式生成前，界面会展示实际纳入资料、估算 Token、警告与裁剪原因。

生成第 N 章时，角色状态和事实按生效章、失效章及替换关系解析；第 N 章之后的正文、记忆、伏笔推进与回收证据不会提前进入上下文。

AI 正文和改稿均写入修改候选。记忆提取只写入 `MemoryProposal`；用户接受、拒绝或修正后，正式记忆才会变化。正文摘要发生变化时，旧提案自动失效并需要重新分析。

## 5. API 概览

- `/api/novels`：项目、保存、导入、章节和聚合数据。
- `/api/novels/:id/generations`：估算与异步生成任务。
- `/api/novels/:id/generation-jobs`、`/api/jobs/:id`：持久任务历史与单任务详情。
- `/api/jobs/:id/events`：SSE 任务进度。
- `/api/revisions`：AI 候选查询、应用与拒绝。
- `/api/memory-proposals`：记忆提案查询和处理。
- `/api/novels/:id/versions`：检查点、列表和恢复。
- `/api/novels/:id/export/:format`：JSON、DOCX、TXT、Markdown 导出。
- `/api/providers`：文字模型配置；不含图片供应商。

## 6. 验收命令

```powershell
npm run typecheck
npm test
npm run build
npm run test:e2e
```

测试包含六类模板、规划门禁、版本冲突、记忆提案、伏笔生命周期、上下文裁剪和 200 章合成长篇召回。任何日常验收都不得运行 `npm run dist:win`，也不得生成或更新安装包。
